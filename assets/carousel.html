01 / 10

Your coverage number is too high

✗ what people write
samtools depth in.bam | awk '{s+=$3} END {print s/NR}'
✓ what it should be
samtools depth -a in.bam | awk '{s+=$3} END {print s/NR}'
Without -a, samtools depth omits zero-coverage positions entirely, so dividing by NR gives mean depth over covered bases only.

02 / 10

You are counting the same read twice

✗ what people write
samtools view -c -F 4 in.bam
✓ what it should be
samtools view -c -F 0x904 in.bam
-F 4 also counts secondary (0x100) and supplementary (0x800) alignments, so it over-reports.

03 / 10

Your unmapped reads lost their pairing

✗ what people write
samtools fastq -f 4 in.bam > unmapped.fq
✓ what it should be
samtools fastq -f 4 -1 un_R1.fq -2 un_R2.fq -0 /dev/null -s /dev/null -n in.bam
samtools fastq -f 4 in.bam > out.fq interleaves R1 and R2 into one file and drops singletons silently.

04 / 10

Your gene names are silently wrong

✗ what people write
awk -F'\t' '$3=="gene" {print $9}' in.gtf | awk -F';' '{print $1, $3}'
✓ what it should be
awk -F'\t' '$3=="gene" && match($9, /gene_name "[^"]+"/) {print substr($9, RSTART+11, RLENGTH-12)}' in.gtf
Positional parsing (cut -d';' -f3) breaks on genes with no gene_name - common for novel and lncRNA genes - and silently returns gene_source instead.

05 / 10

The pipeline failed and said nothing

✗ what people write
samtools view in.bam | wc -l
✓ what it should be
set -o pipefail; samtools view in.bam | wc -l
By default a pipeline reports only the LAST command's status, so a crashed samtools upstream of wc -l looks like success.

06 / 10

gzip is not bgzip

✗ what people write
gzip -c in.vcf > in.vcf.gz && tabix -p vcf in.vcf.gz
✓ what it should be
bgzip -c in.vcf > in.vcf.gz && tabix -p vcf in.vcf.gz
A plain gzip file cannot be indexed.

07 / 10

merge trusted you to sort first

✗ what people write
bedtools merge -i regions.bed
✓ what it should be
sort -k1,1 -k2,2n regions.bed | bedtools merge -i -
bedtools merge assumes sorted input.

08 / 10

Your subsampled mates no longer match

✗ what people write
seqtk sample -s100 R1.fq.gz 10000 > s1.fq; seqtk sample -s42 R2.fq.gz 10000 > s2.fq
✓ what it should be
seqtk sample -s100 R1.fq.gz 10000 > s1.fq; seqtk sample -s100 R2.fq.gz 10000 > s2.fq
Using a different -s seed for R1 and R2 silently destroys pairing.

09 / 10

pigz did not speed that up

✗ what people write
pigz -dc big.fq.gz | wc -l
✓ what it should be
gzip -dc big.fq.gz | wc -l # same speed; use pigz -p N to COMPRESS
pigz parallelises compression only.

10 / 10

LC_ALL=C is fast, and dangerous

✗ what people write
sort -k1,1 -k2,2n big.bed | join - ids.txt
✓ what it should be
LC_ALL=C sort -k1,1 -k2,2n big.bed | LC_ALL=C join - ids.txt
LC_ALL=C is a large speed-up but it changes collation order.
