Ten bioinformatics one-liners that are quietly wrong

Each of these runs without an error and prints a plausible number. The number is not what you think it is.
01
✗samtools depth in.bam | awk '{s+=$3} END {print s/NR}'
✓samtools depth -a in.bam | awk '{s+=$3} END {print s/NR}'
Without -a, samtools depth omits zero-coverage positions entirely, so dividing by NR gives mean depth over covered bases only (B04)
02
✗samtools view -c -F 4 in.bam
✓samtools view -c -F 0x904 in.bam
-F 4 also counts secondary (0x100) and supplementary (0x800) alignments, so it over-reports (B02)
03
✗samtools fastq -f 4 in.bam > unmapped.fq
✓samtools fastq -f 4 -1 un_R1.fq -2 un_R2.fq -0 /dev/null -s /dev/null -n in.bam
`samtools fastq -f 4 in.bam > out.fq` interleaves R1 and R2 into one file and drops singletons silently (B07)
04
✗awk -F'\t' '$3=="gene" {print $9}' in.gtf | awk -F';' '{print $1, $3}'
✓awk -F'\t' '$3=="gene" && match($9, /gene_name "[^"]+"/) {print substr($9, RSTART+11, RLENGTH-12)}' in.gtf
Positional parsing (`cut -d';' -f3`) breaks on genes with no gene_name - common for novel and lncRNA genes - and silently returns gene_source instead (G02)
05
✗samtools view in.bam | wc -l
✓set -o pipefail; samtools view in.bam | wc -l
By default a pipeline reports only the LAST command's status, so a crashed samtools upstream of `wc -l` looks like success (P06)
06
✗gzip -c in.vcf > in.vcf.gz && tabix -p vcf in.vcf.gz
✓bgzip -c in.vcf > in.vcf.gz && tabix -p vcf in.vcf.gz
A plain `gzip` file cannot be indexed (V12)
07
✗bedtools merge -i regions.bed
✓sort -k1,1 -k2,2n regions.bed | bedtools merge -i -
bedtools merge assumes sorted input (D01)
08
✗seqtk sample -s100 R1.fq.gz 10000 > s1.fq; seqtk sample -s42 R2.fq.gz 10000 > s2.fq
✓seqtk sample -s100 R1.fq.gz 10000 > s1.fq; seqtk sample -s100 R2.fq.gz 10000 > s2.fq
Using a different -s seed for R1 and R2 silently destroys pairing (F03)
09
✗pigz -dc big.fq.gz | wc -l
✓gzip -dc big.fq.gz | wc -l # same speed; use pigz -p N to COMPRESS
pigz parallelises compression only (P01)
10
✗sort -k1,1 -k2,2n big.bed | join - ids.txt
✓LC_ALL=C sort -k1,1 -k2,2n big.bed | LC_ALL=C join - ids.txt
LC_ALL=C is a large speed-up but it changes collation order (P03)
